The 7 rules that survive every document

If you only remember one screen from this page, make it this one. Every doc below is a variation on these themes.

RULE 01

Labels describe the source, not the event. Region, cluster, namespace, app, environment, service — things that are fixed for a given system and produce data continuously.

RULE 02

Unbounded values are never labels. Trace IDs, request IDs, order IDs, user IDs, pod names, timestamps: these belong in the log line, span attributes, or structured metadata.

RULE 03

Cardinality multiplies. Three label keys with 3–5 values each already make dozens of streams/series. Adding one more key multiplies, it does not add.

RULE 04

Don't add a label "just in case." Add it only when a real query needs it. Filter expressions and span filters are fast enough, and they cost nothing at ingest.

RULE 05

Some labels are contractual. job=integrations/db-o11y, kafka_cluster, cluster/namespace/pod on K8s logs — get these wrong and dashboards render empty.

RULE 06

Consistency beats richness. team vs teams, Prod vs prod — one typo becomes unattributed cost and a broken join. Standardise keys, lowercase values.

RULE 07

Measure, then prune. Cardinality dashboards, logcli --analyze-labels, cardinality APIs and Adaptive Metrics exist so you can fix labels with data instead of opinions.
